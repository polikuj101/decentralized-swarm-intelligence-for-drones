# Открытые проблемы стенда Swarm of Drones — задание для разбора (2026-10-26)

Контекст: цель — исправное демо для лидов и инвесторов (5 дронов, PX4 SITL + Gazebo Harmonic в WSL2, CBAA над Zenoh, Qwen2.5-0.5B для приказов, BDA-карточки).
Состояние: стенд стабилен (утечка gz-sim устранена патчем Mesa, коммит `2a81771`), полёт, консенсус, HUD честные; репетиция демо одна из пяти прошла полностью, серия из трёх репетиций показала нестабильность из-за пункта 1.
Журнал решений и измерений: `TODOS.md` (разделы 4d–4g), `AUDIT_ANTIGRAVITY.md`, `docs/gz_leak/REPORT.md`. Скрипты замеров: `docs/gz_leak/` (`collect.py`, `analyze.py`, `zerr.py`), в рабочей папке сессии `denial_summary.py`, `xyseries.py`.

Порядок запуска для любых экспериментов: `./scripts/swarm_fresh.sh` (сбрасывает мир, PX4 раньше агентов), затем приказ в HUD или `DEMO_AUTOPILOT=1 ./scripts/run_demo.sh`. Вотчдог на время тестов ставится на паузу: `touch logs/.watchdog_pause`.

## 1. Навигация без GPS: оптический поток дрейфует на десятки метров (главная проблема демо)

**Симптом.** При отказе GPS (сценарий РЭБ) борты, которые движутся, накапливают ошибку позиции 10–25 % от пройденного пути (до 130 м за 2 минуты). Реальный борт уходит в одну сторону, оценка — в другую; PX4 теряет `xy_valid`, выходит из OFFBOARD в ALTCTL и борт садится. Стоящие борты (HOLD) остаются точными (≤ 2 м).

**Что известно (измерено против поз Gazebo).**
- `vio_node.py`: фазовая корреляция кадров нижней камеры (L8, 320×240, hfov 1.2) × высота по нисходящему дальномеру → скорость → `VehicleOdometry` (только скорость, `EKF2_EV_CTRL=4`, `EKF2_EV_NOISE_MD=1`). Масштаб VIO/истина в среднем 1.0, угол ошибки 1–6°, но выбросы (масштаб 0,03–0,15, угол до 134°); фильтр выбросов добавлен (`swarm/altitude.py: vio_outlier`), без GPS опорной скорости PX4 нет.
- Реальная частота кадров камеры 1–6 Гц при заданных 8–15 (см. п. 2); при крейсерской скорости 3 м/с кадры почти не перекрываются. Введён потолок 1 м/с без GPS (`swarm/supervise.py: speed_cap`): помогает, не лечит.
- Вертикальную скорость VIO в EKF больше не подаём (давало раскачку по высоте 0–30 м).
- Данные последней серии: `/tmp/collect_run{1,2,3}.jsonl` в WSL (формат — `collect.py`).

**Нужно.** Способ держать ошибку позиции < 5 м за 2–3 минуты полёта без GPS, либо убедительно обосновать, что в симуляторе этого не достичь и демо надо строить на коротких всплесках (сейчас 45 с, `scenarios/05_investor_demo.yaml`).
Идеи: фьюжн с IMU (ковариации, а не голая скорость), feature-based одометрия (ORB/KLT) вместо фазовой корреляции, оценка yaw-дрейфа, использование барометра/лидара для масштаба, проверка знаков (N/E) и систематической ошибки угла камеры, подача PX4 нормальных дисперсий, торможение/зависание при росте неопределённости.

## 2. Пропускная способность рендера сенсоров (WSL2, Mesa D3D12)

**Симптом.** 15 рендерящихся сенсоров (по борту: камера, `gpu_lidar` 360°, `gpu_lidar` на 1 луч) отдают 40–60 % заданной частоты, под нагрузкой — 1–3 Гц. Это упирается в п. 1 и в обход препятствий.
**Известно.** Утечку (кэш command signature в Mesa d3d12) исправили, но производительность не исследована; `gpu_lidar` дороже камер; `libgz-rendering8-ogre1` установлен (ogre1 не пробовали); Gazebo под Windows нативно не пробовали.
**Нужно.** Профилирование рендера, дешёвые замены (CPU-лидар через физику, один общий проход, меньше лучей/сектор), либо вынос рендера.

## 3. Обнаружение подмены GPS (дрейф)

**Симптом.** Дрейф 2 м/с: `gps_suspect` поднимается через ~40 с в одном прогоне и не поднимается за 75 с в другом; EKF PX4 сначала сопротивляется, потом делает скачок на десятки метров. Когда подозрение поднимается поздно, привязка VIO берётся на уже смещённой позиции (абсолютная ошибка ~70 м).
**Где.** `swarm/flight_ctrl.py: _monitor` (окно 6–10 с, порог 3 м + 15 %, 3 подряд), `swarm/supervise.py: suspect_may_clear`. Тест V3 (`scripts/stress_test.py`) честно проваливается по дрейфу.
**Нужно.** Надёжный детектор по скоростям/инновациям (а не по смещению позиции за окно) и привязка к последнему заведомо хорошему состоянию.

## 4. «Обнаружения цели» нет

Рой знает цели из `scene.json`; `evidence.py` подписывает «ближайшую известную цель». Камера чёрно-белая (L8), цели — цветные диски (на кадре виден светлый диск без цвета). Для честного демо нужен хотя бы простой детектор на кадре (яркость/контур диска) либо цветная камера, плюс изменение формулировок в HUD. Решение продуктовое: оставить как «выход в точку и съёмка» или добавить детекцию.

## 5. Qwen2.5-0.5B разбирает приказы с точностью ~20 % (по полям `on_target`, `zones` хуже)

Флагманская фраза про квадрат «Браво» даёт сектора [0,1,4] вместо [4]. Модель недетерминирована между вызовами (`cache_prompt`), борты расходятся (HUD выравнивает по большинству). Варианты в `TODOS.md` п. 1 (правила для зон, пост-проверка вывода, больше примеров/модель крупнее). Решение за владельцем продукта.

## 6. Протухшая сессия DDS PX4↔агент

После перезапуска только агента PX4 пишет «connected», но `Payload tx = 0 B/s`, борт не взлетает. Обход: `scripts/swarm_fresh.sh` и сторож (`scripts/gz_watchdog.py` перезапускает такой PX4). Причина в клиенте uxrce_dds PX4 1.15 не найдена.

## 7. Воспроизводимость сборки

Образ `drone-agent` собирается `FROM swarm/drone-agent:latest` (из своей же предыдущей сборки), `LLAMA_CPP_REF`/`GGML_FLAGS` не используются; образы `drone-agent` (15.10) и `px4-sitl` (02.10) устарели, исправления держатся на bind-mount. Пакеты Mesa `+swarm1` в репозитории собраны не нами, пересборка не проверялась.

## 8. Безопасность (не блокирует демо)

Один общий ключ роя и 4-байтовый HMAC без nonce (защита от повторов эвристическая, `swarm/replay.py`); ew-controller и gps-bridge без токена (только loopback/mgmt-net); `scripts/proxy_hud.py` слушает `0.0.0.0` и обходит проверку сети оператора (файл не в git, лучше удалить); токены в истории git (`7e1ae74`) заменены новыми в локальном `.env`.
